# STOP-AND-WAIT ARQ

> A sphere of **UD0** — the ROOT0 universe / biosphere. Domain: **HERMES**.

STOP-AND-WAIT ARQ — HERMES: how do you send a file PERFECTLY over a line that loses packets? Send one, wait for the acknowledgement, and if it never comes, send it again. Simple — and provably reliable: every packet arrives, in order, however bad the channel. ⚑ LIVE full-house instrument: raise the loss rate and watch packets drop, retransmit, and still fill the delivered bar to 20/20; the link with drops &amp; retries in 3D; tesseract 4D + shadow + toddler. ◆ LIT: a 1-bit sequence number dedups the duplicate a lost ACK creates; a fail-loud self-check runs 20 packets over a seeded 40%-loss channel and throws unless all 20 arrive exactly once, strictly in order. ▲ AMBER: correct but slow — one packet in flight wastes long links (sliding-window/Go-Back-N fix throughput); losses modelled independent, real ones are bursty.
